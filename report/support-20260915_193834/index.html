结论、限制与下一步

  1. 几何错误主要前移，而不是消失。新版有 skill Medium 的蓝图预演仍有 2 次重叠、2 次面占用，之后 26 个正式组件批次全部成功；无 skill 为 1 次面占用，5 个正式批次全部成功。预演同时还有面标签错误，完整失败列表保存在数据 JSON 中。
  2. 已有承载成功案例，但不能声称 skill 的普遍因果收益。各成品只有一次物理测试，材料用量、生成配置和建模历史不同。Soft 两臂不是同一批完整成功样本；Medium 无 skill 有人工中断与框架修正续跑。
  3. 下一步优先缩短草拟与整机装配上下文。将组件接口、相对变换和连接清单结构化交接，减少整份块摘要重复发送；保留权威状态和可追溯失败证据，不以有损摘要代替几何事实。
  4. 在同一冻结蓝图上单独验证框架收益。使用一致模型、提示配置与任务预算，对比单步 / 批量执行；记录请求数、输入输出 Token、等待、预演、压缩与修复时间，再运行多次游戏仿真。不要用不同规模设计得出固定加速倍数。
  5. Skill 内容改进遵循“短说明 + 代码检查 + 回归用例”。已知非法端点由共享工具阻止；经验解释适用条件。强度、摩擦和连接刚度仍需游戏数据校准，不能只凭平衡公式保证安全。

统计口径

① 所有 Token 为已记录用量或下界，不是费用账单，不推断供应商未返回的重试 / 在途用量。② request_end 与 DB 汇总是重叠口径，绝不直接相加。③ 驱动 elapsed_seconds 为原单调时钟记录；阶段 DB duration 为原墙钟记录，二者可能明显不同。④ M2N 的驱动时间只含续跑；“创建至更新”包含等待和干预，并非纯运行时间。⑤ 物理分数 null 表示没有测量，0 表示已测量但未达到规则；不能合并。⑥ 通过标记为既有分析器结果，未改变高度、时长或荷载定义。⑦ 报告未调用模型重新建桥，也未重新运行游戏。
